# design-sync notes — crm_recruitment

Repo-specific gotchas for future syncs. Read this before re-running.

## Shape of this repo

- This is a **Next.js application**, not a published component library: no
  `dist/`, no `main`/`module`/`exports` in `package.json`. The converter runs in
  **synth-entry mode**, bundling straight from `components/ui/*.tsx`.
- Because there is no dist entry, the build is invoked with a deliberately
  **non-existent `--entry`**:
  `--entry ./.design-sync/no-dist.js`. That path exists only to make the
  converter resolve `PKG_DIR` to the package root (it walks up from the entry to
  the nearest named `package.json`); `resolveDistEntry` then soft-fails and falls
  back to synth mode. Without `--entry` the run dies with
  `ENOENT ... node_modules/crm_recruitment/package.json`, because an app is never
  installed into its own `node_modules`. The `[NO_DIST] --entry ... doesn't
  exist` line in the log is therefore **expected, not an error**.
- Not a git repository (neither `C:\dev\CRM` nor the package), so nothing here
  has been committed. If the repo is ever `git init`-ed, commit the durable set:
  `config.json`, `NOTES.md`, `conventions.md`, `previews/`, `docs/`,
  `safelist.css`, `build-css.mjs`, `font-face.css`, `fonts/`.

## Build order (matters)

1. `node .design-sync/build-css.mjs` — **always before** the converter.
2. `node .ds-sync/package-build.mjs --config .design-sync/config.json --node-modules ./node_modules --entry ./.design-sync/no-dist.js --out ./ds-bundle`
3. `node .ds-sync/package-validate.mjs ./ds-bundle`

`.design-sync/types/` (the `.d.ts` tree the prop contracts come from) is
generated by `npx tsc -p .design-sync/tsconfig.types.json`, then
`.design-sync/types/index.d.ts` is a hand-written barrel re-exporting each
`components/ui/*` module. **Regenerate both whenever a component is added or its
props change**, or the new component's `.d.ts` will be an empty
`[key: string]: unknown` bag. `package.json` carries
`"types": "./.design-sync/types/index.d.ts"` purely so the converter's
`findTypesRoot` locates that tree — it is unused by Next.

## CSS: three things the plain Tailwind output would miss

`build-css.mjs` produces `.design-sync/compiled.css`, which is `cfg.cssEntry`.

- **Preview classes.** Tailwind v4 skips dot-directories, so classes used only in
  `.design-sync/previews/*.tsx` need the explicit `@source "../previews/**/*.tsx"`.
- **A utility safelist** (`.design-sync/safelist.css`). Tailwind only emits
  classes it finds in source, but the design agent writes *new* layouts —
  `grid-cols-3`, `max-w-3xl` etc. were absent until safelisted. Two syntax traps
  found the hard way:
  - every `@import` must precede any `@source` in the entry file, or the
    safelist is only partly applied (invalid CSS at-rule ordering);
  - variants must use the brace form `{hover:,}bg-primary`. A bare
    `hover:bg-primary` inside `@source inline(...)` is silently **not** expanded.
- **Brand fonts.** `app/layout.tsx` loads DM Sans / Noto Serif / Geist / Geist
  Mono via `next/font/google` at runtime, so nothing shipped and every design
  would have rendered in a fallback face. `.design-sync/font-face.css` +
  `.design-sync/fonts/*.woff2` (variable, latin subset, fetched from Google
  Fonts) are prepended to the compiled CSS and define `--font-sans`,
  `--font-heading`, `--font-geist-sans`, `--font-geist-mono`.

## Known render warns (expected — not new findings)

- `[TOKENS_MISSING]` for `--available-height`, `--anchor-width`,
  `--transform-origin`: Base UI sets these at runtime on the positioner. `--tw`
  is a Tailwind-internal registered property. All four are correct to be absent
  from static CSS.
- `[EXPORT_COLLISION] lucide-react exports 2 name(s) the main package also
  exports: Badge, Table`. Deliberate: `cfg.extraEntries: ["lucide-react"]` puts
  the icon set on `window.CrmRecruitment` so the design agent can use icons. The
  DS's own `Badge`/`Table` win, which is the wanted behaviour; the lucide icons
  of those two names are simply unreachable.

## Component API traps (also in conventions.md)

- `DropdownMenuLabel` outside a `DropdownMenuGroup` throws
  "MenuGroupContext is missing" and renders nothing — this failed the first
  render check.
- `SelectContent` defaults `alignItemWithTrigger={true}`, overlaying the list on
  the trigger and clipping the first group label. Previews pass `false`.
- `DropdownMenuContent` takes the trigger's anchor width; with an icon trigger
  the items wrap. Previews set `w-56`.
- `Card size="sm"` downsizes `CardTitle` via a `group-data` variant that beats a
  plain `text-2xl` utility.

## Card modes

`cfg.overrides`: `Dialog`, `DropdownMenu`, `Select` are `cardMode: "single"` with
a viewport (their popups are fixed/portalled and would escape a grid cell);
`Table`, `Input`, `Tabs` are `cardMode: "column"` after `[GRID_OVERFLOW]` flagged
them as wider than a grid cell.

## Re-sync risks

- **The `.d.ts` tree goes stale silently.** It is generated, not watched. A new
  component added to `components/ui/` without re-running the `tsc` step and
  updating the barrel ships with an empty props contract, and the design agent
  will then guess at the API. This is the single most likely regression.
- **Fonts are a point-in-time fetch.** `.design-sync/fonts/*.woff2` were
  downloaded from Google Fonts once. They are not refreshed; if the brand fonts
  change in `app/layout.tsx`, re-run the fetch and rewrite `font-face.css`.
- **The safelist is a guess at what the agent needs.** It is broad but finite. If
  designs come back with unstyled gaps, the missing utility family belongs in
  `safelist.css` — check the compiled CSS for the class before assuming a
  component bug.
- **Preview classes depend on build order.** Editing a preview without re-running
  `build-css.mjs` leaves its new utilities out of the shipped CSS; the card then
  renders subtly wrong while validate still passes.
- **53 of 63 components ship the floor card** (all the sub-parts: `Card*`,
  `Table*`, `Dialog*`, `DropdownMenu*`, `Select*`, `Tabs*`, `Avatar*`). That is
  deliberate — they are exercised inside their parents' authored previews. Any
  re-sync may author them incrementally; grades and authored files carry forward.
- Toolchain at time of sync: node 24.18, pnpm 11.10, Tailwind CLI 4.3.3,
  playwright 1.62.0 (pinned to match the cached chromium build 1234 — the repo
  itself has no playwright dependency).
